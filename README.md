# Offtracq

Source for **[offtracq.com](https://offtracq.com)** — the site for the [Offtracq](https://www.youtube.com/@Offtracq) YouTube channel.

Offtracq is a cinematic travel and adventure film series: hiking, kayaking, off-roading, via ferrata, tribal cultures, spiritual towns, and the hidden places worth going off the beaten path for.

This is a personal-brand marketing site, not a web app — it has no login, no database, and no server of its own. It's a static site that pulls in live YouTube content at build time and lets visitors send a message through a contact form, without ever exposing the owner's real email address in the page.

---

## Tech stack

- **React 19 + TypeScript** — UI
- **Vite** — dev server and production bundler
- **Plain CSS** ([src/index.css](src/index.css)) — no CSS framework, hand-tuned for the site's dark, editorial look
- **lucide-react** — the three content-pillar icons on the homepage
- **YouTube Data API v3** — fetched once at build time, not from the browser
- **Web3Forms** — relays contact-form submissions to an inbox without exposing that inbox
- **GitHub Actions + GitHub Pages** — CI/CD and hosting

## How the site is put together

`src/App.tsx` is one component tree, section by section: nav → hero → content pillars → videos → shorts → Instagram callout → about → contact → footer. A few small reusable pieces live in the same file:

- **`Reveal`** — wraps a section so it fades/slides in the first time it scrolls into view (`IntersectionObserver`-based, respects `prefers-reduced-motion`).
- **`Thumbnail`** — renders a video's thumbnail image, falling back to a plain "OFFTRACQ" placeholder tile if the image fails to load.
- **`ContactForm`** — the get-in-touch form (see [Contact form](#contact-form) below).
- Skeleton loading states render in place of the video/shorts grids while `public/youtube.json` is being fetched client-side.

## Environment variables

Copy the template and fill in real values:

```bash
cp .env.example .env
```

| Variable | Used by | Purpose |
|---|---|---|
| `YOUTUBE_API_KEY` | `scripts/fetch-youtube.mjs` (build time only) | Authenticates with the YouTube Data API v3 to pull the channel's latest videos and shorts. **Never reaches the browser.** |
| `YOUTUBE_CHANNEL_ID` | `scripts/fetch-youtube.mjs` (build time only) | Which channel to pull from (`UCT0q7anHOtvKZTV6t0dBszg` for Offtracq). |
| `VITE_WEB3FORMS_ACCESS_KEY` | `src/App.tsx` (bundled into the client) | Lets the contact form submit to Web3Forms. Safe to expose — it can only submit *to* the configured inbox, it can't read or change anything. |

`YOUTUBE_API_KEY` needs the **YouTube Data API v3** enabled for the project in [Google Cloud Console](https://console.cloud.google.com/), and the key should be restricted there (API restrictions → limit to YouTube Data API v3) since it has real quota tied to it.

`VITE_WEB3FORMS_ACCESS_KEY` comes from a free account at [web3forms.com](https://web3forms.com) — create it there, tied to the inbox that should receive messages.

## Local development

```bash
npm install
npm run dev
```

Opens at `http://localhost:5173` (or the next free port). Vite's dev server doesn't run the YouTube fetch automatically — if `public/youtube.json` doesn't exist yet, run `npm run fetch-youtube` once first.

### Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Starts the Vite dev server with hot reload. |
| `npm run fetch-youtube` | Calls the YouTube Data API and (re)writes `public/youtube.json`. |
| `npm run build` | Runs `fetch-youtube`, typechecks (`tsc -b`), then builds production assets to `dist/`. |
| `npm run lint` | Runs ESLint over the project. |
| `npm run preview` | Serves the `dist/` build locally, to sanity-check a production build before deploying. |

## Contact form

Visitors fill in their email and a message; nothing is ever sent through a `mailto:` link, so the owner's real email address never appears in the page source. Submission flow:

1. The form POSTs (via `fetch`) to Web3Forms' API, including the public access key from `VITE_WEB3FORMS_ACCESS_KEY`.
2. Web3Forms forwards the message to the inbox tied to that key in their dashboard.
3. A hidden checkbox (`botcheck`) acts as a honeypot — real visitors never see or fill it, but spam bots that auto-fill every field do, letting Web3Forms silently drop the submission.
4. The UI shows an inline "sending…" state, then either a success message or a friendly error pointing to Instagram as a fallback.

## Build

```bash
npm run build
```

This (1) fetches the latest videos/shorts, (2) typechecks the whole project, (3) builds to `dist/`. All three must pass for the GitHub Actions deploy to succeed.

## Deployment

Pushing to `main` triggers [.github/workflows/deploy.yml](.github/workflows/deploy.yml):

1. Checks out the repo, installs dependencies, builds the site (same `npm run build` as above).
2. Uploads `dist/` as a Pages artifact and deploys it to GitHub Pages.
3. Also runs on a schedule (every 12 hours) and via manual trigger, so the video list stays fresh even without a code change.

**Required GitHub repo secrets** (Settings → Secrets and variables → Actions):

- `YOUTUBE_API_KEY`
- `YOUTUBE_CHANNEL_ID`
- `WEB3FORMS_ACCESS_KEY`

**Required one-time repo setting**: Settings → Pages → Source → **GitHub Actions**.

### Custom domain (offtracq.com via GoDaddy)

The [public/CNAME](public/CNAME) file tells GitHub Pages which domain to serve. On the DNS side (GoDaddy → DNS management for `offtracq.com`), remove any existing parking records and add:

| Type | Name | Value |
|---|---|---|
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME | www | `<github-username>.github.io` |

Once DNS propagates, enable **Enforce HTTPS** in the repo's Pages settings.

## Security notes

- `.env` is gitignored — never commit real API keys. `.env.example` is the template that *is* committed.
- The YouTube key is used only server-side (at build time, including in CI); it's not part of the shipped JS bundle.
- The Web3Forms key is meant to be public — it only allows submitting to one pre-configured inbox.
- Images in `public/images/` are compressed for web delivery — if you replace `hero.jpg` or `about.jpg`, keep new files well under ~1MB (originals were 63MB/4.2MB before compression and would badly hurt load time).

## Troubleshooting

- **`tsc` fails with "Cannot find module 'react'" or similar** — a `node_modules` install is missing type packages; run `npm install` again (this project depends on `@types/react`, `@types/react-dom`, and `@types/node` as devDependencies).
- **`npm run lint` fails with "command not found"** — same fix, `npm install`.
- **Build succeeds locally but Actions fails** — almost always a missing/misnamed repository secret (see the three secrets listed above).
- **Contact form always errors** — check that `VITE_WEB3FORMS_ACCESS_KEY` is set (locally in `.env`, in CI as the `WEB3FORMS_ACCESS_KEY` secret) and that the Web3Forms key hasn't been revoked.
